# Требования к PlinkoHG

Источник задания: [HG Studio — Defold](https://hgstudio.notion.site/Defold-4236ab52e6804f6db582c60d2f59d387).
ТЗ требует физику падения через кегли, не задаёт лимита одновременно падающих шаров и не требует конкретно Box2D. Пример оформления разрешено интерпретировать свободно. Сохранение и изменение числа корзин перечислены как дополнительные задания; сервер и межпроцессный доступ в исходное ТЗ не входят.
Этот документ фиксирует требования и границы реализации, а не результаты запуска или приёмки.

## Обязательные требования

| Область | Ожидаемое поведение |
| --- | --- |
| Игровое поле | Классический Plinko: шар движется сверху вниз через ряды штырей и попадает в нижнюю корзину. |
| Корзины | В исходной конфигурации 10 корзин. У каждой отдельно задаются вероятность попадания и количество очков. |
| Распределение | Вероятности задаются вручную в конфигурации. Фактические попадания должны соответствовать этому распределению на большой выборке. |
| Результат | Завершивший падение шар засчитывается ровно один раз; начисляются очки соответствующей корзины. |
| Запас шаров | Количество доступных шаров ограничено. Запуск расходует запас; при отсутствии шаров обычный запуск недоступен. |
| Восстановление | Один шар восстанавливается каждые настраиваемые N секунд, пока запас ниже настраиваемого максимума. |
| Отладочная выдача | Отдельное действие добавляет шары и может превысить обычный максимум. Избыток не должен обрезаться следующим обновлением. |
| Управление | Кнопки одиночного запуска, запуска серии и отладочного добавления шаров. |
| Интерфейс | Видны текущий запас шаров, таймер восстановления и накопленный счёт. |
| Статистика | Отладочный вывод показывает число попаданий в корзины, начисленные очки и фактические проценты попаданий. |

## Дополнительные требования

- Сохранение игрового состояния между запусками.
- Изменение числа корзин через конфигурацию без ручной перестройки интерфейса и логики.

## Уточнения реализации

- Визуальная траектория должна завершаться в корзине, выбранной по её настроенной вероятности. Случайная физика сама по себе не гарантирует произвольное заданное распределение.
- Взвешенный выбор допускает веса, не складывающиеся в 100: доля корзины равна её весу, делённому на сумму весов. Нулевой вес исключает корзину из выбора; отрицательные, нечисловые веса и нулевая общая сумма считаются ошибкой конфигурации.
- Статистика попаданий рассчитывается по завершившим падение шарам. Шары в полёте ещё не входят в знаменатель; при отсутствии попаданий проценты отображаются как ноль.
- Восстановление останавливается на максимуме и при превышении максимума отладочной выдачей. Поведение сохранённого таймера, времени вне игры и незавершённых падений должно быть явно описано в архитектуре.
- Серия не должна создавать отрицательный запас или дважды списывать один и тот же шар. Повторный ввод, завершение игры во время серии и временные задержки кадров должны обрабатываться явно.
- Число корзин, оформление, значения наград и вероятностей должны происходить из одной конфигурации, чтобы подписи, геометрия и статистика не расходились.

## Отладочный текст и API Defold

В формулировке задания упоминается `render:draw_text`. Для реализации используется документированный механизм Defold: сообщение `draw_debug_text` на адрес `@render:`; render script выводит материал с тегом `debug_text` через соответствующий предикат `render.draw()`. Это сохраняет требуемый отладочный способ вывода. См. [Render API](https://defold.com/ref/stable/render/#draw_debug_text) и [руководство по рендерингу](https://defold.com/manuals/render/).

## Критерии качества

- Доменная логика запаса, восстановления, выбора награды и статистики отделена от GUI, игровых объектов и рендера.
- Все пользовательские строки находятся в каталоге локализации; интерфейс поддерживает кириллицу.
- Конфигурация валидируется до запуска игровой сессии, сохранения имеют версию и безопасную обработку повреждённых данных.
- Состояние и жизненный цикл имеют явных владельцев; завершение падений, таймеров и обработки ввода не оставляет дублирующихся подписок или начислений.
- Оформление: муравьиная тема IDDLEX, земляные и зелёные оттенки, янтарные шары, разборчивые значения наград и спокойная анимация обратной связи. Декоративные муравьи размещены по краям поля; механики и терминология ТЗ сохранены.

## Проверка реализации

Домен, сохранения, GUI/mesh и ввод проверяются Lua-спецификациями, изолированными сценариями Defold и WebGL. Команды доступны в [README](../README.md#проверки); решения и ограничения описаны в [архитектуре](ARCHITECTURE.md).

## Уточнение автора: расширение наград

По дополнительному запросу автора корзина теперь содержит расширяемый набор Rewards. Реализованы очки, шары и предметы; новый тип добавляется handler/view/регистрацией. Исходная конфигурация сохраняет 10 корзин и прежние points-награды задания. Антураж остаётся стилизацией, игровые области или новые режимы не добавлены. По прямому решению автора прежние сохранения не мигрируются.

## Уточнение автора: заменяемое сохранение

Источник сохранений заменяется отдельно от локальной игровой логики через асинхронный ISessionRepository. Задержки, подтверждения, повторные запросы, конфликт версии и lifecycle обрабатывает application-слой. Рабочая реализация остаётся файловой; сервер не добавлен. Контракт: [PERSISTENCE_CONTRACT.md](PERSISTENCE_CONTRACT.md).
